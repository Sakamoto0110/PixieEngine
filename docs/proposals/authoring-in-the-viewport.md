## PIXIE-PROPOSAL-006

**State:** promoted

**Idea:** After PIXIE-PROPOSAL-005, a project can be made, coded, saved, and played, but a scene is
still built by typing positions into the inspector. This phase makes the editor a place to build a
scene with the mouse and the keyboard, before sprites or exporting a game. Two parts.

1. **What the engine provides.** The engine stays the only copy of the state, and the editor stays
   thin:
   - **Entities by scene ID.** The C API gives an entity's scene ID and finds the live entity with
     a scene ID. An entity's handle changes when the World is built again (Play, Stop, Rebuild,
     restoring an entity); its scene ID does not, so whatever the editor remembers across those
     (undo, redo) refers to entities by scene ID.
   - **Entity snapshots.** The `runtime` writes a set of scene entities as a scene fragment, in
     the scene format (`WriteEntities`), and reads one back into the World (`ReadEntities`), either
     with the same scene IDs (to bring back what was deleted) or with new ones (to duplicate).
     Within a set read back with new IDs, an `Entity` field that pointed inside the set points to
     the new copy; one that pointed outside keeps its target. Unknown components and fields travel
     with the snapshot as they do with a scene.
   - **Names.** The C API writes an entity's `Name`.
   - The C API goes to version 6 with these.
2. **What the editor does with it.**
   - **Moving in the viewport.** In Select mode, pressing on an entity and dragging moves it, and
     the whole selection with it when it was selected; pressing on empty space still selects by
     box. Shift holds the drag to the axis it moved most along. A Snap toggle on the toolbar, with
     a grid size (8, 16, 32, or 64 world units), rounds positions while dragging. A drag that
     moves nothing (a click) only selects, as now.
   - **Undo and redo.** Ctrl + Z undoes, Ctrl + Y and Ctrl + Shift + Z redo, and an Edit menu
     shows both with what they would undo or redo ("Undo move of 3 entities"). Every change to
     the scene in edit mode is one step: a field edited in the inspector (a scrub or a drag on a
     field is one step, from press to release), moving, creating, deleting, duplicating, adding or
     removing a component, and renaming. Steps refer to entities by scene ID. The history lives in
     the editor's memory, for one session; it is kept through Play and Stop, which bring the scene
     back as it was, and through Save. Changes made while playing are not steps, since Stop
     discards them, and undo and redo wait for Stop. Entities without a scene ID (generated by the
     game's code) are not part of the history.
   - **Duplicate and delete.** Ctrl + D, and Duplicate in the viewport's menu, duplicate the
     selection a little to the side and select the copies; Delete deletes the selection, from the
     viewport or the entity list, unless a text field has the keyboard.
   - **Rename.** The inspector shows the selected entity's name in a text field at its top.

Out of this phase: rotating and scaling by hand in the viewport, copying between projects, undo
history kept on disk, multiple scenes, sprites, and exporting a game.

**Rationale:** Building a scene is the editor's main job, and it is slow while every position is
typed and every mistake must be fixed by hand. Undo is planned with the first editing gestures,
before more of them exist, so each new gesture comes with its step. Keeping undo in the editor, on
snapshots and scene IDs that the engine provides, keeps the World the single source of truth and
needs no history inside the engine.

**Constraints:** The engine never depends on the editor: snapshots, scene-ID lookup, and names are
general features of the `runtime` and the C API, usable by any tool or test. The editor remains
portable: no gesture or shortcut assumes Windows.
