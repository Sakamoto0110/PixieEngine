## Choices made while building it

- The code is generated by a CMake script, `cmake/PixieAddCode.cmake`, which both the editor and the
  test run, so there is one generator and the test exercises the same files a user gets.
- The engine reads `PROJECT_IS_TOP_LEVEL`: as a subproject it builds no samples or tests by default,
  leaves `CMAKE_RUNTIME_OUTPUT_DIRECTORY` to the game's project, and skips `pixie-scene-capi`, so a
  game's build never overwrites the library an open editor holds in the engine's `bin/`.
  `pixie_add_capi_library` and `pixie_game` find their files through
  `CMAKE_CURRENT_FUNCTION_LIST_DIR`, so they work when a game's project calls them.
- `pixie_target_defaults` sets the static C++ runtime on every target it touches, so a game's
  targets link with the engine's libraries whatever the game's project sets.
- The player's `main` is a source file compiled into each player rather than a library, and it
  finds its project by walking up from the executable, so `bin/<config>/<Id>.exe` plays where it
  was built, from any working directory.
- `ProjectApp` plays a project it has open, since a player always plays.
- The options every player takes moved from `samples/common` into the engine
  (`pixie/RunOptions.hpp`, `RunOption`, `ParseRunOptions`), and the samples use them there;
  `samples/common` is gone, ahead of PIXIE-TASK-101, which expected it to keep only what the engine
  does not provide: nothing was left.
- The library a project opens with is the one `*-capi` library in `<project>/bin/<config>/`, so the
  editor needs no naming rule beyond `pixie_game`'s. The editor builds its own configuration
  (Debug or Release).
- Because P/Invoke binds one library per process, every build that must replace a loaded library
  happens in a new editor: Add code and Build and reopen restart the editor with `--project` and
  `--after <pid>`, and the new one waits for the old one to exit before building. Opening a project
  with code after creating one on the start screen, which binds the generic library, also opens a
  new editor.
- When the build fails, Open without code opens the scene with the generic library; components only
  the code knows are kept as raw data and written back.
